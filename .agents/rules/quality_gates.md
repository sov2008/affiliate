# Регламент четырехуровневых барьеров качества (Quality Gates Protocol)

**Версия:** 2.0.0  
**Область действия:** Монорепозиторий Antigravity Affiliate  

---

## Уровень 1: Локальный самоконтроль разработчика (L1: Self-Check)
* **Исполнитель:** `agent-core-developer`
* **Триггер:** Завершение генерации или модификации кода перед передачей на ревью.
* **Обязательные проверки:**
  1. `npm run typecheck` — сквозная проверка типов TypeScript в `src/` и `core/src/` с нулевым количеством ошибок.
  2. `npm --prefix blog run build` — верификация статической компиляции блога Astro и AST-шаблонов.
  3. Проверка отсутствия неявных типов `any` и временных подавлений компилятора (`@ts-ignore`).
* **Критерий прохождения:** Код возврата 0 на всех проверочных командах.

---

## Уровень 2: Аудит комплаенса и реальных данных (L2: Compliance & Zero-Demo)
* **Исполнитель:** `agent-qa-gatekeeper`
* **Триггер:** Подача изменений на слияние в рабочую ветку.
* **Обязательные проверки:**
  1. `npm run audit` — запуск аудита трекинговых ссылок, прелендингов и антифрод-защиты.
  2. Сканирование измененных файлов на соответствие правилу **Strict Zero Demo Data** (отсутствие `Math.random` в метриках, отсутствие моков в проде).
  3. Проверка всех партнерских ссылок на атрибуты `rel="nofollow sponsored"` и `target="_blank"`.
  4. Проверка корректности макросов динамического трекинга (`s1-s5` для LosPollos, `sub1-sub5` и `click_id` для MyLead).
  5. Проверка языковой политики: публичный UI и контент обязаны быть на 100% чистом английском языке (Strict English).
* **Критерий прохождения:** Формирование подписанного отчета `[APPROVED]` без блокирующих дефектов.

---

## Уровень 3: Предрелизный CI-пайплайн (L3: CI Pre-Merge)
* **Исполнитель:** GitHub Actions (`ci-cd.yml`, `deploy.yml`) под контролем `agent-devops-engineer`
* **Триггер:** Push / Pull Request в ветку `main`.
* **Обязательные шаги пайплайна:**
  1. Чистая установка зависимостей (`npm ci`).
  2. Полный `npm run typecheck`.
  3. Выполнение набора регрессионных тестов:
     - `antifraud-trust.spec.ts`
     - `link-integrity.spec.ts`
     - `gold-catalog.spec.ts`
     - `postback.spec.ts`
  4. Сборка производственного дистрибутива `core/dist` и `blog/dist`.
* **Критерий прохождения:** Зеленый статус всех джобов в GitHub Actions.

---

## Уровень 4: Пост-деплой валидация в продакшене (L4: Post-Deploy Health Check)
* **Исполнитель:** `agent-sre-guardian`
* **Триггер:** 30 секунд после перезапуска PM2 / пересборки контейнера на сервере.
* **Обязательные проверки:**
  1. HTTP GET `http://127.0.0.1:5000/api/health` — код ответа 200, uptime > 0.
  2. Проверка статуса 9 PM2 процессов (`pm2 status`) — статус всех демонов `online`, отсутствие циклов падения (`restart_count < 3`).
  3. Проверка целостности SQLite баз данных (`PRAGMA integrity_check;`) и активности режима WAL.
  4. Проверка отсутствия флага экстренной остановки (`.antigravity/halt.flag`).
* **Критерий прохождения:** Подтверждение штатной работы узла. При сбое — немедленная активация отката (Rollback).
